# Troubleshooting

**The binary is missing.** Run `bash "${CLAUDE_PLUGIN_ROOT}/scripts/install-binary.sh"`. It provisions the release pinned by the plugin version — a brew-installed `cc-review` wins, otherwise it downloads to the durable plugin data dir — and leaves `bin/cc-review` as a symlink to the payload. The SessionStart hook runs this automatically on the first session.

**No comment notifications arrive.** Confirm the Monitor is running (`/tasks`) and that you launched it with `persistent: true`. `cc-review watch` writes one line per event straight to stdout (unbuffered), so as long as the Monitor is armed, each comment becomes a notification. Check the daemon is up with `"${CLAUDE_PLUGIN_ROOT}/bin/cc-review" status`.

**No Monitor tool in this session.** Headless/cron and some providers (Bedrock/Vertex/Foundry, telemetry disabled) expose no Monitor, and channels aren't active there either. Step 3's decision tree routes you on: `reference/route-teams.md` when agent teams are on (a `SendMessage` tool exists), else `reference/route-streamer.md` (a one-shot streamer subagent), else `reference/route-inline.md`. Each streams `watch --once` (exit-per-event) and relays each event to you until `submit`; cursor-resume loses nothing across cycles.

**`channel: pending` printed / tags never arrive.** `pending` is wired-but-unproven: the channel server is attached, and that start just injected a `channel.probe` tag into it to prove delivery. The Monitor is the route — arm it exactly as on `inactive`. On the first `<channel source="cc-review">` tag (the probe or a real event), run `"${CLAUDE_PLUGIN_ROOT}/bin/cc-review" channel-ack --session "$CLAUDE_CODE_SESSION_ID" --cwd "$PWD"` so future starts in this window print `active`. No probe tag within a few seconds means Claude Code is silently dropping channel notifications — sessions launched without `--channels`, or where Claude Code prints *"--channels ignored"* / *"Channels are not currently available"*, correctly stay `pending` or `inactive`.

**A flood of comments stopped the Monitor.** Monitors stop themselves under a high event rate. Re-arm the Monitor; `watch` resumes from its cursor, so you miss nothing.

**Events replayed after re-arming a Monitor.** Delivery is at-least-once: a Monitor re-armed in a later session can replay events you already handled as channel tags. Dedupe by event id and treat already-handled events as informational — replies dedupe server-side, and organize dispatch dedupes by request id.

**Edits are blocked.** That's the point: the PreToolUse guard denies edits while a review is open. It lifts once the human presses Submit and the review status becomes `submitted`, or when the review expires — an open review idle for 24 hours (no comments, replies, AI-bar activity, or new versions) expires on its own. The human can repair a stuck state themselves: `cc-review close [review]` closes a review without submitting, and `cc-review list` shows every open review with age, idle time, and repo. Those are the human's commands — never run `close` to unblock your own edits. If the daemon is down, the guard fails open (edits are allowed).

**The review didn't resume.** Resume follows the Claude *window*: `/clear` and resume in the same window pick an open review back up (the branch is never part of the key, so a mid-review checkout won't fork it either); an expired one needs an explicit `start`. A *different* window never adopts another window's review — its `start` always creates its own. Pass `--new` if you wanted a fresh review instead.

**The stream went quiet after a plugin upgrade.** Upgrading replaces the daemon mid-session; streams refresh their connection automatically, but a watcher built by the old binary may stop. Re-arm the Monitor — `watch` resumes from its cursor, so nothing is lost. On the streamer fallback there's nothing to re-arm: each cycle re-execs the binary, so the next relaunch is already the new build.

**Nothing to review.** In a git repo, `start` snapshots the uncommitted working tree (tracked, staged, and untracked, minus ignored) against `HEAD` — or the empty tree when the repo has no commits. In a jj repo (including colocated), it snapshots the working-copy change (`@`) against its parent. With no changes, the diff is empty.
